## Rule No. 1 — Respect each other's time

Avoid wasting time on unproductive work. The group reserves specific time slots for meetings, so use them effectively. Initiate experiments **at least the next day after each meeting** — analysis, debugging, and reflection require adequate time. If you can only begin experiments one day before a meeting, reschedule the meeting instead.

Slack is the primary communication channel. Use `#random` for casual questions.

## Weekly expectations

### Weekly report

Consult experienced students for the current format.

### Individual meeting prep

Review [this post on being a successful PhD student](https://cs.stanford.edu/~ihazan/) — the *You and Your Advisor* section is particularly valuable.

Meeting materials should contain:

- **Context refresh** (1–2 minutes): Outline project objectives and current phase goals so the meeting doesn't open with clarification.
- **Completed work from previous week.**
- **Results and conclusions**: Highlight key takeaways rather than reciting raw data.
- **Encountered challenges** and proposed solutions for the coming week.

### Paper reading

- Engage with papers in the `#paper-reading` channel.
- Participate in weekly group meetings.
- Volunteer for presentations covering your research or interesting publications.

## Code

- Establish a **private GitHub repository** per project within the LIME organization.
- Polish code following submission; share code and datasets upon paper acceptance.
- Leverage branches and tags to document experimental results.
- Use issues and wikis for tracking development and tests.
- **Commit regularly** — server infrastructure lacks backup systems.

## Project logs

- Set up a Slack channel per project named `proj-xxx`; add collaborators as guests if external.
- Document progress continuously; pin log links.
- Record experimental parameters and primary findings.
- Note emerging ideas for future exploration.

## Internal deadlines

Faculty manage competing priorities. For submissions:

| Submission timing | Expected feedback |
|---|---|
| ≥ 2 weeks before | Thorough, iterative comments |
| 1 week before | Abstract and introduction assistance; surface-level review |
| < 1 week before | Limited depth possible |

**Insufficient time remaining?** Papers lacking a complete draft one week prior likely shouldn't be submitted.

**Draft requirements**: narrative framework established; minimum 50% content complete; placeholders acceptable for tables and related work. Conduct a thorough self-review using standard paper-writing guidelines.
